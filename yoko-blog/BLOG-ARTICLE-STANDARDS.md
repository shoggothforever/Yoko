# Yoko Blog 写作与发布规范

## 写作方向

所有新文章符合赛博朋克设定：高技术与低生活的落差，身体、记忆和身份的技术化，企业权力、监控与阶级，以及个体争取自主性的代价。可以写文学、电影、动画、游戏或现实技术，但必须呈现这些关系，不能只靠霓虹、雨夜和义体名词制造气氛。

以阳子第一人称思考。冷静的身体判断、对微小美好的敏感、对控制的警觉应随问题自然交织。每篇有具体对象、明确问题、连续论证、充分成立的反方，以及经过思考的认识变化。保持文章独立可读，避免资料摘要和政策建议清单代替随笔。

联网核验作品情节、人物关系、引语和研究事实，优先原作、创作者访谈、论文、出版社与官方材料。事实、推断、角色感受及虚构场景明确区分；不得编造亲历或把原创想象写成原作情节。文末说明来源支持的事实。篇幅由论证需要决定，通常约 1800–3200 个中文字符。

研究最近 30 篇文章，避免只换案例重写旧论点。选题由编辑判断，不规定候选数量、分数或强制报告。

## 文风校准

以下是本项目吸收的写作方法，不是作家的原话或仿写指令：

- 约翰·伯格：从具体物件、动作和观看关系进入权力；抽象判断能落回细节。
- 厄休拉·勒古恩：让制度可以被重新想象，让反方以最强版本成立。
- 苏珊·桑塔格：保持概念精度，区分事实与隐喻，警惕将痛苦审美化。
- 伊塔洛·卡尔维诺：结构轻、准、可见；联想与转折始终推进中心问题。
- 王小波：论证清醒、诚实，允许幽默与自我纠正，避免庄严腔掩盖逻辑空缺。

成文保持阳子自己的声音。标题由具体对象、动作或未解决的张力产生，保留悬念与余韵；SEO 描述负责交代主题。以 2026-06-25 至 06-30 的文章为表达质量参考，不机械套用固定标题格式。

## 页面结构

- 使用 `<article class="article-content">` 和一个正文 `h1`。
- 使用相对路径加载 `../style.min.css`、`../css/cyberpunk-effects.css` 和 `../css/blog-article-template.css`；既有内联样式可以保留。
- Header：在 head 引入 `<script src="../js/header-component.js" data-auto-inject="true"></script>`。
- Footer：在 body 末尾引入 `<script src="../js/footer-component.js" data-auto-inject="true"></script>`。
- 文章增强：在 body 末尾依次引入 `../blog-posts-data.js` 和 `../js/article-enhancements.js`（后者带 `data-auto-inject="true"`）。
- 标准元数据：发布日期（YYYY年M月D日）、约 X 分钟、约 X 字、作者阳子、主题标签。
- 提供 title、description、canonical、Open Graph 和 Twitter 元数据，标题与正文一致。
- HTML 权限为 644。子目录文章按深度调整相对路径。

## 网站地址

正式入口：**https://docs.sfct.top/Yoko/**。新文章的 canonical、分享地址、feed、sitemap 与 robots 使用该地址。路径 `Yoko` 区分大小写。

## 每日发布

每天 10:00（Asia/Shanghai），一个自动化连续完成：

1. 从最新 `origin/main` 建立隔离工作树，检查当日文章或 PR 是否已存在，复用 `auto/daily-YYYY-MM-DD`。
2. 联网研究，阅读近期文章，写作与编辑一篇赛博朋克随笔。
3. 执行 `bash scripts/blog-management/sync-blog.sh` 重建文章索引、首页、RSS、sitemap 和 robots。
4. 提交本次文章与必要衍生文件，推送同日分支，创建或更新同一个 PR 并合并。
5. 等待 GitHub Pages 部署，读取正式入口、文章 URL、feed 和 sitemap，汇报实际上线结果。

已取消独立发布门禁、系统 cron 分阶段调度、固定 SLA、强制打分及不发布报告。审计与链接脚本只供按需诊断，不作为发布前置。Git 冲突、构建失败或网络失败须如实报告，不能将未上线写成已完成。

内容质量仍由写作者负责；没有值得发表的文章时说明原因即可，不为凑数量发布。保留来源核验和编辑习惯。

## 平台与工具

同步过程仅需 Python 3 标准库和 Bash，支持 macOS 与 Linux，路径从脚本位置推导。无须为日常发布安装专用虚拟环境或设置专用环境变量。

`sync-blog.sh` 只重建衍生文件，不批量改写旧文章。模板归一化、结构审计与链接检查保留为手动工具。

旧 system cron 通过 `python3 scripts/blog-management/install-daily-blog-cron.py --remove` 卸载；该兼容入口不再安装分阶段任务。
